简单说：**MCP 是协议标准，FastMCP 是让这个标准用起来更顺手的 Python 框架。**

### MCP 是什么：协议层

MCP（Model Context Protocol）是一个开放协议，让 LLM 应用能以标准化的方式连接外部数据源和工具。它定义了三类核心角色：

- **Host**：LLM 应用本身（比如 Claude Desktop、Cursor）
- **Client**：Host 内部的连接器，负责与 Server 通信
- **Server**：提供上下文和能力的外部服务

Server 向 Client 暴露三种能力：**Resources**（可读取的数据）、**Prompts**（可复用的提示模板）、**Tools**（LLM 可调用的函数）。`@mcp.tool` 就是在提供 Tools 这一类能力。

底层通信走 JSON-RPC，支持 stdio（本地子进程）和 HTTP（远程服务）两种传输方式。

### FastMCP 是什么：实现层

FastMCP 是一个 Python 框架，它把 MCP 协议的底层细节（JSON Schema 生成、消息编解码、传输管理）封装起来，让你只需要写普通的 Python 函数，就能得到符合 MCP 标准的 Server。

你已经在用的核心模式：

```python
from fastmcp import FastMCP

mcp = FastMCP("MyServer")          # 创建服务器容器

@mcp.tool                           # 把函数注册为 Tool
def greet(name: str) -> str:
    """向指定的人打招呼。"""
    return f"Hello, {name}!"

mcp.run()                           # 启动服务器
```

FastMCP 会自动读取函数签名和类型注解，生成对应的输入 Schema，LLM 客户端靠这个 Schema 知道该怎么调用你的工具。参数没有默认值就是必填，有默认值就是可选，遵循 Python 的函数参数约定。

> fastMCP服务跑起来之后，可以使用`npx @modelcontextprotocol/inspector python mcp_server.py`测试下

### 接下来可以深入的方向

**方向一：Resources 和 Prompts**

Tools 之外，MCP 还有两种能力。`@mcp.resource` 暴露只读数据（比如配置文件、文档内容），`@mcp.prompt` 定义可复用的提示模板。它们和 Tool 的区别在于：Tool 由 LLM 决定何时调用，Resource 由客户端主动读取，Prompt 通常由用户选择触发。

**方向二：把服务器接到真正的 LLM 客户端**

你现在的客户端是自己写的 Python 脚本。更有意义的用法是把 FastMCP 服务器配置到 Claude Desktop、VS Code（Copilot）或 Cursor 里，让模型自己决定什么时候调用你的工具。配置方式通常是在客户端的配置文件里加一条 stdio 启动命令，指向你的 `mcp_server.py`。

**方向三：Structured Output**

FastMCP 支持工具返回结构化的类型（Pydantic 模型、TypedDict、dataclass 等），会自动生成输出 Schema 并做验证。如果你的工具需要返回复杂数据（比如一个包含多字段的查询结果），用结构化输出比返回拼接字符串更规范。
