# 受控表单 + 组件通信 + 单向数据流

这三个其实是**同一个主题的三个侧面**：数据怎么流动。表单是"数据从 DOM 流回 state"，组件通信是"数据在组件间流动"，单向数据流是"数据只能朝一个方向流动"的规则。学完你会发现它们是闭环的。

## 1 受控 vs 非受控

**受控（controlled）**：表单的值由 React state 决定，用户的输入先写入 state，再由 state 渲染回输入框。

**非受控（uncontrolled）**：值存在 DOM 自己身上，React 通过 ref 去读，不参与管理。

```jsx
// 受控：value 来自 state，onChange 把输入写回 state
<input value={name} onChange={e => setName(e.target.value)} />

// 非受控：DOM 自己管值，需要时用 ref 读
const ref = useRef();
<input ref={ref} defaultValue="初始值" />;
// 读：ref.current.value
```

**本质区别**：受控的"真相"在 state，非受控的"真相"在 DOM。

**React 推荐受控**，因为：

- 单一数据源，界面 = f(state)，可预测
- 能即时校验、格式化、联动
- 能程序化地重置/赋值

非受控只在"文件上传 `<input type="file">`"、"简单表单不关心中间状态"等少数场景用。

## 2 受控 input / textarea / select

### input（text）

```jsx
function NameForm() {
  const [name, setName] = useState("");
  return (
    <div>
      <input
        value={name}
        onChange={e => setName(e.target.value)}
        placeholder="请输入名字"
      />
      <p>你输入了：{name}</p>
    </div>
  );
}
```

**两个必写**：`value`（受控的标志）+ `onChange`（把变化写回 state）。**只写 value 不写 onChange = 只读输入框**，用户敲什么都进不去，控制台还报警告。

### textarea

React 里 `textarea` 和 `input` 一样用 `value`（不是 HTML 的 `<textarea>内容</textarea>`）：

```jsx
const [bio, setBio] = useState("");
<textarea value={bio} onChange={e => setBio(e.target.value)} rows={4} />
```

### select

用 `value` + `onChange`，不再用 HTML 的 `selected` 属性：

```jsx
const [city, setCity] = useState("bj");
<select value={city} onChange={e => setCity(e.target.value)}>
  <option value="bj">北京</option>
  <option value="sh">上海</option>
  <option value="gz">广州</option>
</select>
```

### 一个完整的受控表单

```jsx
function SignupForm() {
  const [form, setForm] = useState({
    username: "",
    password: "",
    city: "bj",
    agree: false,
  });

  // 通用 change 处理：用 name 区分字段
  const handleChange = (e) => {
    const { name, value, type, checked } = e.target;
    setForm(prev => ({
      ...prev,
      [name]: type === "checkbox" ? checked : value,  // 造新对象！
    }));
  };

  const handleSubmit = (e) => {
    e.preventDefault();   // 阻止表单默认刷新页面的行为
    console.log(form);
  };

  return (
    <form onSubmit={handleSubmit}>
      <input name="username" value={form.username} onChange={handleChange} />
      <input name="password" type="password" value={form.password} onChange={handleChange} />
      <select name="city" value={form.city} onChange={handleChange}>
        <option value="bj">北京</option>
        <option value="sh">上海</option>
      </select>
      <label>
        <input name="agree" type="checkbox" checked={form.agree} onChange={handleChange} />
        同意协议
      </label>
      <button type="submit">提交</button>
    </form>
  );
}
```

**这里的几个关键点**（呼应你之前学过的）：

- `setForm(prev => ({...prev, [name]: value}))`——**造新引用**，否则 React 不更新
- checkbox 用 `checked` 而不是 `value`，取的是 `e.target.checked`
- `handleSubmit` 里必须 `e.preventDefault()`，否则浏览器会刷新整页（这是表单最常见的坑）

### 表单陷阱速查

| 陷阱 | 症状 | 修法 |
|------|------|------|
| 只写 value 没写 onChange | 输入框只读 | 补 onChange |
| onChange 里直接改 state 对象 | 不更新 | 造新对象 `{...prev}` |
| 忘 `e.preventDefault()` | 提交后整页刷新 | 加 preventDefault |
| checkbox 用 value | 拿不到勾选状态 | 用 `e.target.checked` |
| value 为 null/undefined | 警告"uncontrolled → controlled" | 初始值设 `""` |
| 用 `value` 又想设默认值 | 设了 value 就成受控，defaultValue 无效 | 两者别混用 |

## 3 组件通信 + 单向数据流

### 单向数据流的定义

**数据只能从父流向子，子不能直接改父的数据。** 子想改，只能通过父传下来的回调"通知"父，由父去改。

```
父 state ──props──▶ 子组件（读）
                      │
                      │ 用户操作
                      ▼
                调用 props 里的回调
                      │
                      ▼
父收到通知 ──▶ 父改 state ──▶ 重新渲染 ──▶ 子收到新 props
```

**数据流是"父 → 子"，但事件流是"子 → 父"（通过回调）。** 两条线，方向相反，但都符合单向数据流——因为**改数据的永远只有父**。

### 回调 props 的标准写法

```jsx
// 父：持有 state，定义修改逻辑，通过回调传给子
function Parent() {
  const [count, setCount] = useState(0);

  const increment = () => setCount(c => c + 1);   // 父是唯一能改 count 的人

  return (
    <div>
      <p>count: {count}</p>
      <Child count={count} onIncrement={increment} />
    </div>
  );
}

// 子：只读 props，想改就调回调
function Child({ count, onIncrement }) {
  return (
    <div>
      <span>收到 count: {count}</span>
      <button onClick={onIncrement}>+1</button>   {/* 不直接改，通知父 */}
    </div>
  );
}
```

**子组件绝不能**：

- 直接 `count = count + 1`
- 直接改父传下来的对象属性
- 自己维护一份"和父重复的 state"然后试图同步（除非确实需要本地草稿）

### 子组件想改自己内部的东西怎么办？

**自己的 state 自己改，没问题。** 单向数据流只管"跨组件"：

```jsx
function Child() {
  const [local, setLocal] = useState(0);   // 自己的 state，自己改，天经地义
  return <button onClick={() => setLocal(local + 1)}>{local}</button>;
}
```

**判断标准**：数据是谁的，就由谁改。父的归父，子的归子。

### 兄弟组件通信（中间人模式）

兄弟之间不能直接传，只能**状态提升**到共同父级：

```jsx
function Parent() {
  const [selected, setSelected] = useState(null);   // 状态提升

  return (
    <>
      <List onSelect={setSelected} />       {/* 子 A 改 */}
      <Detail item={selected} />            {/* 子 B 读 */}
    </>
  );
}
```

**"状态提升"** = 把多个子组件都要用的 state 提到共同父级，然后通过 props 下发、通过回调上传。

### 深层嵌套通信：Context

如果隔了五六层，一层层传 props（叫 "prop drilling"）会很难受。这时用 Context：

```jsx
const ThemeContext = createContext("light");

function App() {
  return (
    <ThemeContext.Provider value="dark">
      <DeepChild />
    </ThemeContext.Provider>
  );
}

function DeepChild() {
  const theme = useContext(ThemeContext);   // 直接拿，不用一层层传
  return <p>主题：{theme}</p>;
}
```

**Context 没有破坏单向数据流**——它只是把"传递方式"从逐层 props 改成了"就近广播"，**数据来源仍然是祖先**。

## 4 受控表单 + 组件通信 结合：一个真实例子

**待办清单的输入框拆成子组件，由父管理数据。**

```jsx
// 父：持有 todos 和输入内容
function TodoApp() {
  const [todos, setTodos] = useState([]);
  const [input, setInput] = useState("");

  const addTodo = () => {
    if (!input.trim()) return;
    setTodos(prev => [...prev, { id: Date.now(), text: input, done: false }]);
    setInput("");
  };

  const toggleTodo = (id) => {
    setTodos(prev =>
      prev.map(t => (t.id === id ? { ...t, done: !t.done } : t))
    );
  };

  return (
    <div>
      <TodoInput value={input} onChange={setInput} onAdd={addTodo} />
      <ul>
        {todos.map(t => (
          <li key={t.id} onClick={() => toggleTodo(t.id)}>
            {t.done ? "✅" : "⬜"} {t.text}
          </li>
        ))}
      </ul>
    </div>
  );
}

// 子：纯受控输入 + 调回调
function TodoInput({ value, onChange, onAdd }) {
  return (
    <div>
      <input
        value={value}
        onChange={e => onChange(e.target.value)}
        onKeyDown={e => e.key === "Enter" && onAdd()}
      />
      <button onClick={onAdd}>添加</button>
    </div>
  );
}
```

**这里把所有知识点串起来了**：

- `value` + `onChange` → 受控输入
- `onAdd` / `onChange` → 回调 props
- 数据在父，子在读、在通知 → 单向数据流
- `setTodos(prev => [...prev, ...])` → 不可变更新
- `key={t.id}` → 列表 key

## 5 常见错误写法对照

```jsx
// ❌ 子组件偷偷改父数据
function Child({ todos }) {
  todos.push(newTodo);   // 改父对象，不更新，还乱
}

// ✅ 调回调让父改
function Child({ onAdd }) {
  onAdd(newTodo);
}

// ❌ 子自己维护一份和父重复的 state，试图同步
function Child({ value }) {
  const [local, setLocal] = useState(value);
  useEffect(() => setLocal(value), [value]);   // 同步地狱
  // 大多数情况直接受控更好
}

// ✅ 子直接受控，不存副本
function Child({ value, onChange }) {
  return <input value={value} onChange={e => onChange(e.target.value)} />;
}
```

## 🏋️ 练习

**练习 1**：写一个受控的"登录表单"：用户名、密码、一个"记住我"checkbox，提交时 `console.log` 出对象，阻止默认刷新。

**练习 2**：找 bug

```jsx
function Form() {
  const [data, setData] = useState({ name: "" });
  return (
    <input
      value={data.name}
      onChange={e => {
        data.name = e.target.value;   // ❌
        setData(data);
      }}
    />
  );
}
```

答案

两个错：直接改对象属性（违反不可变），且 `setData(data)` 传的是同一个引用（React 跳过更新）。改成 `setData(prev => ({...prev, name: e.target.value}))`。

**练习 3**：把待办清单升级——拆出 `TodoInput` 和 `TodoItem` 两个子组件，父管理 todos 和 input 两个 state，全部通过 props 下发、回调上传。

**练习 4**：思考题——为什么说"回调 props 不违反单向数据流"？

答案

单向数据流约束的是"**数据**只能父→子流"，不约束"**事件/回调**的传递方向"。子通过回调**通知**父，真正**改数据的永远是父**，数据本身仍然只从父流向子。所以本质没变。


## 记忆卡

| 概念 | 一句话 |
|------|--------|
| 受控 | `value` + `onChange`，真相在 state |
| 非受控 | 真相在 DOM，用 ref 读 |
| 单向数据流 | 数据父→子流，改数据只能父改 |
| 回调 props | 子通过它通知父，父去改数据 |
| 状态提升 | 兄弟共享的数据提到共同父级 |
| Context | 解决 prop drilling，但没破坏单向数据流 |
| 表单大坑 | 忘 preventDefault / 直接改对象 / checkbox 用错属性 |
