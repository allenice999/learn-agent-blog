# 环境变量 + Route Handler 写 API 返回 JSON

本门把前面章节的能力接上“后端”：你写的前端代码可以调用自己写的 API 了。核心只有两条：**环境变量分“服务端私有”和“浏览器可见”两类；Route Handler 就是一个导出 HTTP 方法的 `route.ts` 文件。**

## 1 环境变量：`.env.local` 与 `NEXT_PUBLIC_` 前缀

Next.js 内置从 `.env*` 文件加载环境变量到 `process.env`，不需要装 `dotenv`。

**创建 `.env.local`**（在项目根目录，不是 `src/` 里）：

```txt
# .env.local
DB_HOST=localhost
DB_USER=myuser
DB_PASS=mypassword
NEXT_PUBLIC_ANALYTICS_ID=abc123
```

### 两条铁律

| 变量名 | 谁能访问 | 安全吗 |
|--------|---------|--------|
| `DB_PASS`（无前缀） | **仅服务端**（Server Component、Route Handler） | ✅ 不会进浏览器 |
| `NEXT_PUBLIC_ANALYTICS_ID` | **服务端 + 浏览器都可用** | ⚠️ 会内联进客户端 JS 包 |

**不带 `NEXT_PUBLIC_` 的变量永远不会发送到浏览器**，只能在服务端代码里读。带 `NEXT_PUBLIC_` 的变量会在**构建时**被替换成硬编码值塞进客户端包，**构建后再改 `.env` 不会生效**。

> **安全原则**：密钥、数据库密码、私钥**绝对不加** `NEXT_PUBLIC_`。只有本来就要公开的值（如公开的分析 ID、站点 URL）才加前缀。

### 在 Route Handler 里读私有变量

```ts
// app/api/db-test/route.ts
export async function GET() {
  const host = process.env.DB_HOST;       // ✅ 服务端可以读
  // process.env.DB_PASS 也在这里可用
  return Response.json({ host });
}
```

如果在**客户端组件**（`"use client"`）里读 `process.env.DB_PASS`，拿到的是 `undefined`——因为它根本没被发送到浏览器。

### 陷阱：不要解构 `process.env`

```ts
// ❌ 不要这样做
const { DB_HOST } = process.env;

// ✅ 直接属性访问
const host = process.env.DB_HOST;
```

Next.js 在构建时会做静态替换，解构会让替换失效。

## 2 Route Handler：用 `route.ts` 返回 JSON

### 文件位置决定 URL

```
app/
├── api/
│   ├── hello/
│   │   └── route.ts     → GET /api/hello
│   └── users/
│       └── route.ts     → GET/POST /api/users
```

**规则**：`route.ts` 放在 `app/` 下任意文件夹里，文件夹路径就是 URL 路径。**同一层级不能同时有 `page.tsx` 和 `route.ts`**（冲突）。

### 最简单的 JSON API

```ts
// app/api/hello/route.ts
export async function GET() {
  return Response.json({ message: "Hello from Next.js", time: Date.now() });
}
```

`Response.json()` 是 Web 标准 API，自动设 `Content-Type: application/json`。访问 `/api/hello` 就能拿到 JSON。

### 支持的方法

`GET`、`POST`、`PUT`、`PATCH`、`DELETE`、`HEAD`、`OPTIONS`。导出哪个函数，就响应哪个方法。不支持的方法返回 `405`。

### 读取查询参数

```ts
// app/api/search/route.ts
import { type NextRequest } from "next/server";

export async function GET(request: NextRequest) {
  const query = request.nextUrl.searchParams.get("q");  // /api/search?q=react
  return Response.json({ query, results: [] });
}
```

### 读取 POST body

```ts
// app/api/todos/route.ts
export async function POST(request: Request) {
  const body = await request.json();           // { text: "..." }
  // 这里可以校验、存库
  return Response.json({ id: Date.now(), ...body }, { status: 201 });
}
```

### 返回错误状态码

```ts
export async function GET(request: NextRequest) {
  const id = request.nextUrl.searchParams.get("id");
  if (!id) {
    return Response.json({ error: "缺少 id" }, { status: 400 });
  }
  return Response.json({ id });
}
```

### 动态路由：`[slug]`

```ts
// app/api/posts/[slug]/route.ts
export async function GET(
  request: Request,
  { params }: { params: Promise<{ slug: string }> }
) {
  const { slug } = await params;    // ⚠️ params 是 Promise，必须 await
  return Response.json({ slug, title: `文章 ${slug}` });
}
```

访问 `/api/posts/hello` → `slug = "hello"`。

## 3 把环境变量和 Route Handler 串起来

一个完整的“用私有密钥调用外部 API”的示例：

```ts
// app/api/weather/route.ts
import { type NextRequest } from "next/server";

export async function GET(request: NextRequest) {
  const city = request.nextUrl.searchParams.get("city") || "beijing";

  // ✅ 服务端读私有密钥，浏览器看不到
  const apiKey = process.env.WEATHER_API_KEY;
  if (!apiKey) {
    return Response.json({ error: "服务端未配置密钥" }, { status: 500 });
  }

  const res = await fetch(
    `https://api.example.com/weather?city=${city}&key=${apiKey}`
  );

  if (!res.ok) {
    return Response.json({ error: "上游服务失败" }, { status: 502 });
  }

  const data = await res.json();
  return Response.json({ city, weather: data });
}
```

`.env.local` 里只写 `WEATHER_API_KEY=xxx`，**不加 `NEXT_PUBLIC_`**。前端调用 `/api/weather?city=shanghai`，永远接触不到密钥。

## 4 客户端如何调用这个 API

```tsx
"use client";
import { useState } from "react";

export default function WeatherButton() {
  const [data, setData] = useState(null);

  const load = async () => {
    const res = await fetch("/api/weather?city=shanghai");
    const json = await res.json();
    setData(json);
  };

  return (
    <div>
      <button onClick={load}>查天气</button>
      {data && <pre>{JSON.stringify(data, null, 2)}</pre>}
    </div>
  );
}
```

**注意**：客户端 `fetch("/api/weather")` 只调到你自己的 Route Handler，**不直接调外部 API**，所以密钥安全。

## 5 常见陷阱

| 陷阱 | 后果 | 修法 |
|------|------|------|
| 把密钥加 `NEXT_PUBLIC_` | 密钥进浏览器包，泄露 | 去掉前缀，只在服务端用 |
| 解构 `process.env` | 变量读不到 | 用 `process.env.XXX` |
| `params` 忘了 `await` | 拿到 Promise 而非对象 | `const { slug } = await params` |
| 同一层有 `page.tsx` 和 `route.ts` | 构建报错 | 移到不同路径 |
| 改了 `.env` 没重启 | 变量不更新 | `Ctrl+C` 重启 `next dev` |
| 用 `NEXT_PUBLIC_` 存运行时可变配置 | 构建后冻结，改环境变量无效 | 需要运行时值就通过 API 提供给客户端 |

## 🏋️ 练习

**练习 1**：创建 `.env.local`，设 `SECRET_TOKEN=my-secret` 和 `NEXT_PUBLIC_SITE_NAME=MyBlog`。然后：
- 在 `app/api/check/route.ts` 的 GET 里读 `SECRET_TOKEN`，返回 `{ hasToken: true/false }`
- 在任意页面（Server Component）里显示 `NEXT_PUBLIC_SITE_NAME`

**练习 2**：写一个 `GET /api/greet?name=xxx`，返回 `{ greeting: "Hello, xxx" }`。如果没传 `name`，返回 400 和错误 JSON。

**练习 3**：写一个 `POST /api/echo`，接收 JSON body，原样返回，并加一个 `receivedAt` 时间戳。

**练习 4**：思考——为什么 `SECRET_TOKEN` 在客户端组件里读不到？如果业务真的需要客户端知道某个“秘密”（比如用于前端加密的公钥），该怎么做？

答案

客户端组件读不到是因为没有 `NEXT_PUBLIC_` 前缀的变量**不会被打进浏览器包**。如果需要客户端用某个服务端配置，正确做法是**通过 API 返回给客户端**（比如 `/api/config` 返回公开配置），或者写成 Server Component 的 props 传给 Client Component。**永远不要把真正的秘密发给浏览器。**

## 记忆卡

| 概念 | 一句话 |
|------|--------|
| `.env.local` | 存本地环境变量，自动加载到 `process.env` |
| 无前缀变量 | 仅服务端可读，不进浏览器 |
| `NEXT_PUBLIC_` | 构建时内联进客户端包，构建后冻结 |
| Route Handler | `app/**/route.ts`，导出 `GET`/`POST` 等函数 |
| 返回 JSON | `Response.json(data, { status })` |
| 查询参数 | `request.nextUrl.searchParams.get("key")` |
| 动态路由 | `params` 是 Promise，必须 `await` |
